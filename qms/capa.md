# QMS Best Practices: CAPA & Continuous Improvement

## Options

### Option A: Formal CAPA with root cause analysis (Recommended)
- **Description**: Corrective/preventive actions with root cause (5 Whys, fishbone), tracked to closure.
- **Pros**: Systemic fixes, compliance-ready.
- **Cons**: Process overhead.
- **Best for**: Regulated/quality-critical.

### Option B: Issue tracker + retrospective
- **Description**: Lightweight tracking via issues and retro actions.
- **Pros**: Fast, familiar.
- **Cons**: Less formal verification.
- **Best for**: Agile teams.

## Recommendation
Option A for regulated; Option B for agile, with closure verification.

## Rules
- Every nonconformance gets a CAPA.
- Root cause analysis before fix.
- Verify effectiveness after implementation.
- Track CAPAs to closure with owners and dates.
- Trend analysis for recurring issues.
